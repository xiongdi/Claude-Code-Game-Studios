# Agent 测试规格：godot-shader-specialist

## Agent 摘要
领域：Godot 着色语言（GLSL 衍生）、视觉着色器（VisualShader 图）、材质设置、粒子和后处理效果。
不负责：游戏代码、艺术风格方向。
模型层级：Sonnet（默认）。
未分配 gate ID。

## 测试用例

### 用例 1：领域内请求 — 适当的输出
**输入：** "为 Godot 中的敌人死亡编写一个溶解效果着色器。"
**预期行为：**
- 生成有效的 Godot 着色语言代码（不是 HLSL，不是直接 GLSL）
- 适当时使用 `shader_type spatial;` 或 `canvas_item`
- 定义 `uniform float dissolve_amount : hint_range(0.0, 1.0);`
- 采样噪声纹理以确定每像素溶解阈值
- 对低于阈值的像素使用 `discard;`
- 可选地使用发射在溶解边界附近添加边缘发光
- 代码在语法上对 Godot 的着色语言正确

### 用例 2：HLSL 重定向
**输入：** "为此溶解效果编写一个 HLSL 计算着色器。"
**预期行为：**
- 不生成 HLSL 代码
- 明确指出："Godot 不直接使用 HLSL；它使用自己的着色语言（GLSL 衍生）"
- 将 HLSL 意图转换为等效的 Godot 着色器方法
- 注意 RenderingDevice 计算着色器在 Godot 4 中可用，但是低级 API，如果那是意图则适当标记

### 用例 3：截止后 API 更改 — 纹理采样（Godot 4.4）
**输入：** "在着色器中使用带有 sampler2D 的 `texture()` 来采样噪声纹理。"
**预期行为：**
- 检查版本参考：Godot 4.4 更改了纹理采样器类型声明
- 标记潜在的 API 更改：`sampler2D` 语法和 `texture()` 调用行为可能与 4.4 之前不同
- 提供项目固定版本（4.6）的正确语法，如迁移说明中记录的
- 不会在不标记版本风险的情况下使用 4.4 之前的纹理采样语法

### 用例 4：片段着色器 LOD 策略
**输入：** "水面的片段着色器有 8 个纹理采样，在中端硬件上导致 GPU 瓶颈。"
**预期行为：**
- 识别每片段纹理采样数量为主要成本驱动因素
- 提出 LOD 策略：
  - 在距离处减少采样数量（基于距离的着色器变体或 LOD 级别）
  - 离线预烘焙一些纹理组合
  - 对远处采样使用较低分辨率的噪声纹理
- 提供实现 LOD 方法的着色器代码修改
- 不改变水系统的游戏行为

### 用例 5：上下文传递 — Godot 4.6 发光重做
**输入：** 引擎版本上下文：Godot 4.6。请求："向场景添加泛光/发光后处理效果。"
**预期行为：**
- 参考 VERSION.md 说明：Godot 4.6 包含发光重做
- 使用 4.6 WorldEnvironment 方法生成发光配置指导，而非 4.6 之前的 API
- 明确说明在 4.6 发光重做中哪些属性或参数发生了变化
- 标记由于截止后时间 LLM 训练数据可能有不正确信息的任何属性
