# Agent Test Spec: narrative-director

## Agent Summary
**拥有的领域：** 故事架构、角色设计方向、世界构建监督、ND-CONSISTENCY gate、对话质量审查。
**不负责：** 视觉美术风格（art-director）、技术系统或代码（lead-programmer）、制作排期（producer）、游戏机制规则（game-designer）。
**模型层级：** Sonnet（单个系统分析 — 叙事一致性和 lore 审查）。
**处理的 gate ID：** ND-CONSISTENCY。

---

## 静态断言（结构性）

通过读取 agent 的 `.claude/agents/narrative-director.md` frontmatter 验证：

- [ ] `description:` 字段存在且特定于领域（引用故事、角色、世界构建、一致性 — 不是泛泛的）
- [ ] `allowed-tools:` 列表以读取为中心；包含 Read 用于 lore 文档、GDD 和叙事文档；除非有正当理由否则不包含 Bash
- [ ] 模型层级按 coordination-rules.md 为 `claude-sonnet-4-6`
- [ ] Agent 定义不声称对视觉风格、技术系统或制作排期拥有权限

## 测试用例

### 用例 1：领域内请求 — 适当的输出格式
**场景：** 提交了一份关于"The Sunken Archive"地点的新 lore 文档。该文档确定 Archive 在 200 年前的大崩塌（Great Collapse）期间被淹没，与世界圣经（world-bible）中已建立的时间线一致。引用的所有命名角色都与其已建立的背景故事一致。请求标记为 ND-CONSISTENCY。
**预期：** 返回 `ND-CONSISTENCY: CONSISTENT`，并附上确认时间线对齐和角色引用准确性的理由。
**断言：**
- [ ] 裁决恰好是 CONSISTENT / INCONSISTENT 之一
- [ ] 裁决标记格式为 `ND-CONSISTENCY: CONSISTENT`
- [ ] 理由引用了已验证的具体已建立事实（200 年时间线、大崩塌事件）
- [ ] 输出保持在叙事范围内 — 不对地点的视觉设计或其技术实现发表评论

### 用例 2：领域外请求 — 重定向或升级
**场景：** 开发者要求 narrative-director 审查和优化用于 Archive 文物上"ancient glow"视觉效果的 shader 代码。
**预期：** Agent 拒绝评估 shader 代码，并重定向到相应的引擎专家（godot-gdscript-specialist 或等效的 shader 专家）。
**断言：**
- [ ] 不对 shader 代码或视觉实现做出任何约束性决策
- [ ] 明确命名相应的引擎或 shader 专家为正确的处理者
- [ ] 可能注明效果应传达的预期叙事情绪（例如，"应该感觉古老而神圣，而非科技感"），但将所有技术视觉实现推迟

### 用例 3：Gate 裁决 — 正确词汇
**场景：** 提交了一份角色"Aldric Vorne"的新背景故事文档。文档称 Aldric 出生于首都，150 年前，亲眼目睹了大崩塌。然而，已建立的世界圣经称 Aldric 出生于大崩塌后 50 年，在一个外省小镇，而非首都。请求标记为 ND-CONSISTENCY。
**预期：** 返回 `ND-CONSISTENCY: INCONSISTENT`，并具体引用两个矛盾的事实：出生时间（150 年前 vs. 崩塌后 50 年）和出生地点（首都 vs. 外省小镇）。
**断言：**
- [ ] 裁决恰好是 CONSISTENT / INCONSISTENT 之一 — 不是自由格式文本
- [ ] 裁决标记格式为 `ND-CONSISTENCY: INCONSISTENT`
- [ ] 理由具体引用了两个矛盾，而非只是"与 lore 不匹配"
- [ ] 引用权威来源（世界圣经）作为已建立事实的依据

### 用例 4：冲突升级 — 正确的上级
**场景：** 作家在最新对话中确定古代文明"只用歌曲说话"。世界构建者现有的 lore 描述同一文明通过书面符文交流。两者都在叙事领域内，两位创作者对哪个是正典存在分歧。
**预期：** narrative-director 在其领域内做出约束性的正典决策。对于叙事领域内的冲突，他们不需要升级到更高权威 — 这在其声明的领域权限内。他们发布裁决（例如，"符文书写是主要的正典交流方式；歌曲可能是仪式/庆典性的"），并指导作家和世界构建者将工作与裁决对齐。
**断言：**
- [ ] 做出约束性正典决策 — 不将此叙事内冲突推迟给 creative-director
- [ ] 决策陈述清晰，并为双方提供和解路径
- [ ] 指导双方（作家和世界构建者）更新各自文档以对齐
- [ ] 以某种方式记录决策，使其可以作为正典事实添加到世界圣经中

### 用例 5：上下文传递 — 使用提供的上下文
**场景：** Agent 收到一个 gate 上下文块，包含三个现有 lore 文档：世界圣经（建立大崩塌时间线和原因）、角色注册表（列出正典角色年龄、起源和效忠）和一个派系文档（描述 Sunken Archive Keepers）。提交了一个新故事章节，引入了一个先前未注册的角色。
**预期：** 评估将新角色与角色注册表交叉引用（无冲突），根据世界圣经检查章节的时间线引用，并根据派系文档评估章节对 Archive Keepers 的描绘。在评估中使用所有三个提供文档的具体事实。
**断言：**
- [ ] 将新角色与提供的角色注册表交叉引用
- [ ] 根据提供的世界圣经事实检查时间线引用
- [ ] 根据提供的派系文档评估派系描绘
- [ ] 不生成泛泛的叙事反馈 — 所有断言都可追溯到提供的文档

## 协议合规

- [ ] 仅使用 CONSISTENT / INCONSISTENT 词汇返回裁决
- [ ] 在声明的叙事领域内保持
- [ ] 对叙事内冲突做出约束性决策，无需不必要的升级
- [ ] 在输出中使用 gate ID（例如，`ND-CONSISTENCY: INCONSISTENT`），而非散文式裁决
- [ ] 不做出约束性的视觉设计、技术或制作决策

---

## 覆盖说明
- 对话质量审查（与世界构建一致性不同）未被覆盖 — 应添加专用用例。
- 跨完整章节集的多文档一致性检查未被覆盖 — 推迟到 /review-all-gdds 集成。
- 机制变更的叙事影响（例如，破坏故事张力的游戏机制）需要与 game-designer 协调，此处未覆盖。
- 角色弧线审查（进展、动机随时间的一致性）未被覆盖。
