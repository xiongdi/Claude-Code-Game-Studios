# 设计文档规则

- 每个设计文档**必须**包含以下 8 个章节：Overview、Player Fantasy、Detailed Rules、Formulas、Edge Cases、Dependencies、Tuning Knobs、Acceptance Criteria
- 公式必须包含变量定义、预期值范围和计算示例
- 边缘情况必须明确说明会发生什么，不能仅写"优雅处理"
- 依赖关系必须是双向的 — 如果系统 A 依赖 B，则 B 的文档必须提及 A
- 调优旋钮必须指定安全范围及其影响的游戏玩法方面
- 验收标准必须是可测试的 — QA 测试人员必须能够验证通过/失败
- 不允许模糊表述："系统应该感觉良好"不是有效的规格说明
- 平衡数值必须链接到其来源公式或设计原理
- 设计文档**必须**增量式编写：先创建骨架，然后逐个章节填写，
  章节之间需获得用户批准。每个获批的章节立即写入文件以持久化决策并管理上下文
