# 范围检查

此技能是只读的 — 它报告发现但不写入文件。

将原始计划范围与当前状态进行比较，以检测、量化和分诊范围蔓延。

**参数**：`$ARGUMENTS[0]` — 功能名称、sprint 编号或里程碑名称。

---

## Phase 1: 查找原始计划

定位给定参数的基线范围文档：

- **功能名称** → 读取 `design/gdd/[feature].md` 或 `design/` 中的匹配文件
- **Sprint 编号**（例如 `sprint-3`） → 读取 `production/sprints/sprint-03.md` 或类似文件
- **里程碑** → 读取 `production/milestones/[name].md`

如果未找到文档，报告缺失的文件并停止。没有用于比较的基线就不要继续。

---

## Phase 2: 读取当前状态

检查实际已实现或正在进行的内容：

- 扫描代码库中与功能/sprint 相关的文件
- 读取与此工作相关的 git 提交日志（`git log --oneline --since=[start-date]`）
- 检查指示未完成范围新增的 TODO/FIXME 注释
- 如果功能处于 sprint 中期，检查活跃的 sprint 计划

---

## Phase 3: 比较原始范围与当前范围

生成比较报告：

```markdown
## 范围检查：[功能/Sprint 名称]
生成时间：[日期]

### 原始范围
[原始计划中的项目列表]

### 当前范围
[当前已实现或正在进行的项目列表]

### 范围新增（不在原始计划中）
| 新增项 | 来源 | 时间 | 是否合理？ | 工作量 |
|----------|--------|------|------------|--------|
| [项目] | [提交/人员] | [日期] | [是/否/不明确] | [S/M/L] |

### 范围移除（在原始计划中但已放弃）
| 移除项 | 原因 | 影响 |
|-------------|--------|--------|
| [项目] | [移除原因] | [受影响的内容] |

### 膨胀分数
- 原始项目数：[N]
- 当前项目数：[N]
- 新增项目数：[N]（+[X]%）
- 移除项目数：[N]
- 净范围变化：[+/-N]（[X]%）

### 风险评估
- **进度风险**：[低/中/高] — [说明]
- **质量风险**：[低/中/高] — [说明]
- **集成风险**：[低/中/高] — [说明]

### 建议
1. **削减**：[应移除以按时完成的项目]
2. **延期**：[可以移到未来 sprint/版本的项目]
3. **保留**：[真正必要的新增内容]
4. **标记**：[需要 producer/creative-director 做出决定的项目]
```

---

## Phase 4: 裁决

根据净范围变化分配规范裁决：

| 净变化 | 裁决 | 含义 |
|-----------|---------|---------|
| ≤10% | **PASS**  | 在轨 — 在可接受偏差范围内 |
| 10–25% | **CONCERNS** | 轻微蔓延 — 通过针对性削减可控 |
| 25–50% | **FAIL** | 显著蔓延 — 必须削减或正式延长时间表 |
| >50% | **FAIL** | 失控 — 停止、重新规划、上报给 producer |

突出显示裁决：

```
**范围裁决：[PASS / CONCERNS / FAIL]**
净变化：[+X%] — [在轨 / 轻微蔓延 / 显著蔓延 / 失控]
```

---

## Phase 5: 下一步

展示报告后，提供具体的后续行动：

- **PASS** → 无需操作。建议在下次里程碑前重新运行。
- **CONCERNS** → 提供识别 2-3 个最佳削减比例的新增内容。参考 `/sprint-plan update` 正式重新定义范围。
- **FAIL** → 建议上报给 producer。参考 `/sprint-plan update` 重新规划或 `/estimate` 重新基线化时间表。

始终以以下内容结束：
> "削减完成后再次运行 `/scope-check [name]` 以验证裁决是否改善。"

---

### 规则

- 范围蔓延是没有相应削减或时间表延长的新增内容
- 并非所有新增都是坏事 — 有些是发现的需求。但它们必须被承认和考虑
- 推荐削减时，优先保留核心玩家体验而非锦上添花
- 始终量化范围变化 — "感觉变大了"不可操作，"+35% 项目"可以
